# 04 · 板级配置点、引脚表与资源预算

> ⚠ **本文件受 [07 号文档](07-板级硬件核对与冲突修正.md) 修订（2026-09-21）** —— 本文件被改动的比例最大：
> - **§1 配置宏**：`CAN_*`（改 FDCAN1/PD0,PD1）、`RS485_*`（改 USART2/PD5,PD6）、新增 `ESP_*`、`FLASH_*`（改 SPI2/PB12-PB15）
>   → **请以 [07 §6](07-板级硬件核对与冲突修正.md) 的宏块为准**。
> - **§3 引脚总表**：整体以 [07 §3](07-板级硬件核对与冲突修正.md) 取代。
> - **§4 HAL 模块**：并集里新增 **SPI2**（原按 SPI1）。
> - **§5 NVIC**：`FDCAN2_IT0` → `FDCAN1_IT0`；`USART3_IRQ` → `USART2_IRQ`；新增 ESP-12F 用的 `USART3_IRQ`。
> - **§7 时钟核算**：HAL 时基、`BRR=1302`、FDCAN 位时序、SPI 速率等**全部不变**（USART2 与 USART3 同在 APB1 150 MHz）。
> - **§6 RAM/Flash 预算**：总量不变；Flash 分区增大只影响 W25Q 内部寻址，不占 MCU RAM。

## 1. 单一配置点：`App/app_board_cfg.h`

依据 00 号文档 D-08：**全系统只有这一个头文件允许改，其余模块不得出现板级硬编码**。
合并两工程原有的两个配置入口（`BSP/bsp_board_cfg.h` 的 `MODBUS_NODE_ROLE`、`Drivers/User/Inc/can.h:41` 的 `CAN_NODE_ROLE`）
为一个层次化宏块。

```c
/* ===== 第 0 层：由 Keil Target 的 Define 注入，不要在本文件里改 ===== */
#ifndef NODE_ROLE
  #define NODE_ROLE   NODE_ROLE_GATEWAY     /* 兜底默认，两 Target 都必须显式 Define */
#endif
#ifndef FORM_MODE
  #define FORM_MODE   FORM_M1               /* M1=PC代理上云  M2=设备侧 MQTT-C */
#endif

/* ===== 第 1 层：派生，禁止手改 ===== */
#define USART3_OWNER  (FORM_MODE==FORM_M2 && NODE_ROLE==NODE_ROLE_GATEWAY ? UP3_ESP : UP3_RS485)
#define ROLE_IS_GW    (NODE_ROLE==NODE_ROLE_GATEWAY)
#define ROLE_IS_NODE  (NODE_ROLE==NODE_ROLE_NODE)
#define NODE_ID       (ROLE_IS_GW ? 0 : 1)               /* 决定 CAN ID 低 8 位的 +N */
#define CAN_BASE_ID(n) (0x100 + (n))                     /* TELEMETRY_FAST */

/* ===== 第 2 层：可核算的可调参数（改一处，全局生效） ===== */
#define RS485_DEFAULT_BAUDRATE      115200u
#define RS485_DEFAULT_SLAVE_ID      1u
#define RS485_RX_MODE               0        /* 0=中断逐字节(唯一真机验证过的模式) 1=DMA+IDLE */
#define RS485_USE_DE_PIN            0        /* 板上自动收发电路 */
#define CAN_BITRATE                 500000u  /* 只用经典 CAN 500k */
#define MB_TIMEOUT_MS               100u     /* 沿用 master_main.c */
#define MB_RETRY_MAX                2u       /* 3 次总尝试 */
#define POLL_PERIOD_MS              500u
#define CAN_HB_PERIOD_MS            1000u
#define CAN_LINK_TIMEOUT_MS         3000u    /* 3× 心跳周期（v3.0 是 1500，本系统改 3s 以容 ISO-TP 快照） */
#define CAN_BACKOFF_INIT_MS         1000u    /* bus-off / MQTT 重连共用同一退避序列 */
#define CAN_BACKOFF_MAX_MS          30000u
#define CAN_RX_Q_LEN                32u
#define UPLINK_TELEMETRY_MS         1000u
#define UPLINK_STATUS_MS            5000u
#define UPLINK_COUNTERS_MS          10000u
#define UPLINK_SNAPSHOT_MS          30000u
#define MQTT_KEEPALIVE_S            30u
#define MQTT_QOS_TELEMETRY            0
#define MQTT_QOS_DEFAULT              1
#define MQTT_SEND_BUF               896u     /* snapshot 750B + 头 */
#define MQTT_RECV_BUF               256u
#define MQTT_TOPIC_PREFIX           "gac/line1/gwA"
#define MQTT_BROKER_HOST            "192.168.1.100"   /* PC 的 LAN IPv4，必须显式填 */
#define MQTT_BROKER_PORT            1883u
#define BACKFILL_BURST              8u       /* 每次唤醒最多补发条数 */
#define LOG_QUOTA_EVENT             1024u
#define LOG_QUOTA_PENDING           1024u
#define LOG_CACHE_CAP               128u     /* ★ 由 512 降，回收 12 KB RAM */
#define LCD_CTRL_SELECT             0        /* 0=ST7789 240x280 */
#define CONTRACT_VERSION            1u
#define FW_VERSION_BCD              0x100u   /* 1.0.0 */
```

**验收约束 A-01**：全仓 `grep` 不得出现裸 `USART3` / `GPIO_PIN_10` / `115200` / `0x500` 等字面量出现在
`BSP/` 之外的文件中。CI 脚本 `Tools/ci/check_config_points.sh` 检查（v0.2 引入）。

## 2. Keil 双 Target（v0.1 出口条件）

`MDK-ARM/G474.uvprojx` 内建 4 个 Target，覆盖"角色 × 形态"矩阵（Modbus v2.0 的"4 组合编译矩阵全绿"做法值得沿用）：

| Target | Define | 说明 |
|---|---|---|
| `A_GW_M1` | `USE_HAL_DRIVER,STM32G474xx,NODE_ROLE=0,FORM_MODE=1` | 网关 + PC 代理上云 |
| `A_GW_M2` | `...,NODE_ROLE=0,FORM_MODE=2` | 网关 + ESP-12F/MQTT-C |
| `B_NODE_M1` | `...,NODE_ROLE=1,FORM_MODE=1` | 采集节点（两形态下节点侧代码相同） |
| `B_NODE_M2` | `...,NODE_ROLE=1,FORM_MODE=2` | 同上，用于验证宏泄漏 |

必须做到：**两个 `NODE_ROLE` 值下所有单元都能编译**（M1/M2 用 `#if FORM_MODE` 隔离 `Network/`），
且 `B_NODE_*` 编译产物不含 `modbus_master` 引用、`A_GW_*` 不含 `slave_main` 的 UI 代码。
用 `MDK-ARM/build_check.log` 记录每次全量编译（沿用 Modbus 工程既有做法）。

⚠ 修正既有缺陷：v2.0 里 `master_main.c` / `slave_main.c` **没有** `#if MODBUS_NODE_ROLE` 守卫，
两者永远一起编译链接（`build_check.log` 可证），与自身 `docs/01 §3` 矛盾。新工程必须在文件首尾加守卫。

## 3. 引脚总表（合并后，含冲突核查）

| 引脚 | 功能 | AF/模式 | 归属模块 | 冲突核查 |
|---|---|---|---|---|
| **PB10** | USART3_TX | AF7（**唯一 USART 复用**） | RS485 DI 或 ESP-12F RX | 与 WiFi 互斥，由 `USART3_OWNER` 决断 |
| **PB11** | USART3_RX | AF7（**唯一 USART 复用**） | RS485 RO 或 ESP-12F TX | 同上 |
| PB12 | FDCAN2_RX | AF9 | CAN | ✔ 已实测；**Modbus `docs/02:12` 误写为 FDCAN1，需改** |
| PB13 | FDCAN2_TX | AF9 | CAN | ✔ |
| PA9 | USART1_TX | AF7 | console + M1 上行 | ✔ 与 FDCAN2 共存已实测 |
| PA10 | USART1_RX | AF7 | console | ✔ |
| PA4 | SPI1_NSS(软) | GPIO Out | W25Q128 CS | ✔ |
| PA5/PA6/PA7 | SPI1 SCK/MISO/MOSI | AF5 | W25Q128 | ✔ 模式 0，`BAUDRATEPRESCALER_16` → 实际 **9.375 MHz**（代码注释"170/16≈10.6 MHz"是按 170 MHz 内核时钟算的，本板 150 MHz，注释错） |
| PA15 | I2C1_SCL | AF4 | 24C02 | ⚠ **JTDI**，必须锁 SWD 2-pin |
| PB9 | I2C1_SDA | AF4 | 24C02 | ✔ |
| PB3 | LCD_SCL | GPIO Out（软 SPI） | TFT | ⚠ **JTDO/TRACESWO**，禁用 Trace |
| PB5 | LCD_SDA | GPIO Out | TFT | ✔ |
| PD11/PD12/PD13 | LCD_CS/DC/BL | GPIO Out | TFT | ✔ |
| PA0/PA2/PA3 | WKUP/K0/K1 | In + 上拉 | 按键 | ✔ 无 EXTI，轮询式 `KEY_Scan` |
| PE0/PE1 | LED 蓝/绿 | GPIO Out，低有效 | 状态灯 | ✔ v3.0 已改用 `GPIOE->BSRR` 原子写（`TogglePin` 的 ODR 读改写曾在 sniff 高负载下丢写） |
| 时钟 HSE 8 MHz | PLL M/2 N75 R/2 | | SYSCLK 150 MHz | AHB/APB1/APB2 全 /1 = 150 MHz；`FLASH_LATENCY_4`；`SCALE1` |
| DMA1_Ch2 | USART3_RX（DMAMUX，circular 512 B） | | 仅 `RS485_RX_MODE==1` | ⚠ 默认模式 0 时不占 DMA |

**核查结论**：合并后无新增引脚冲突。唯一硬冲突是 PB10/PB11 的 RS485⊕WiFi（已由 00 号文档 §1.2 定策）。
历史上这里还埋过一个真机故障：LCD 跨端口引脚掩码 bug 曾误改 **PB11 = USART3_RX**，导致从站静默收不到帧
（Modbus 工程 commit `85be08b`）。→ **验收 A-09 专项**：上电后读 `GPIOB->MODER`/`AFR` 断言 PB10/PB11 为 AF7 复用态，
不通过则 panic + 串口报引脚归属。这类"隔空改寄存器"的 bug 只能靠断言捕获。

## 4. HAL 模块裁剪合并

两工程 `stm32g4xx_hal_conf.h` 的 `HAL_MODULE_ENABLED` 集合不同，合并时取并集：

| 模块 | CAN 工程 | Modbus 工程 | 合并后 |
|---|---|---|---|
| FDCAN | ✅ | ❌ | ✅ |
| USART + **UART_EX** | ✅（用了 `hal_uart_ex.c`） | ✅ | ✅ |
| SPI / I2C / DMA / DMAMUX | ❌ | ✅ | ✅ |
| **ADC** | ❌ | ❌ | ✅（02 号文档决策 7 需要） |
| TIM（TIM6 = HAL 时基） | ❌ | ❌ | ✅ |
| CRC | ❌（被注释掉） | ❌ | ❌ —— 用软件 `MODBUS_CRC16`，保持与 Python/Node 交叉验证一致，不引入硬件 CRC 造成第二套真相 |
| IWDG | ✅ | ❌ | ✅（两板都开） |
| FLASH | ❌ | ❌ | ❌（不写内部 Flash；参数在 24C02） |

⚠ HAL 库版本必须锁定 **STM32G4 HAL V1.2.3 + DFP 2.2.0**（CAN 工程实测版本，其代码内含三处针对该版本的规避：
排空后手工清 `hfdcan->ErrorCode`、`FDCAN_IT_TX_COMPLETE` 需配 `BufferIndexes=0x07` 置 TXBTIE、
`hiwdg.Instance` 空指针导致 HardFault）。升级 HAL 版本 = 重新验证这三处，不要顺手升。

## 6. RAM / Flash 预算

**G474VET6 = 512 KB Flash / 128 KB SRAM**（96 KB SRAM1 + 32 KB SRAM2）。

### 6.1 RAM

| 项 | M1（A 板） | M2（A 板） | B 板 | 依据 |
|---|---|---|---|---|
| v2.0 基线静态 (RW+ZI) | 19.2 KB | 19.2 KB | 19.2 KB | `build_check.log`: `RW=24 ZI=19152` |
| └ 其中 `LOG_CACHE_CAP` | 4 KB（512→128 后） | 4 KB | 4 KB | 决策 6；**回收 12 KB** |
| FreeRTOS 内核 + 队列 | 3 KB | 3 KB | 3 KB | 队列 7×（can_rx 512 B、uart ring 2×512 B、log 2 KB 等） |
| 任务栈 T1–T7 | 15 KB | 15 KB | 13 KB | 7 任务合计 4352 word = 17.4 KB（含 T4=1024w）；B 板无 T4 |
| `configTOTAL_HEAP_SIZE` | 20 KB | 20 KB | 18 KB | 栈从 heap 分配，含 20 % 余量 |
| MQTT-C 收发缓冲 | — | 1.15 KB | — | 896 + 256（03 号文档 §5.1） |
| esp_at/JSON 组包 | — | 1.5 KB | — | snapshot 分片 ×2 |
| dp_table 镜像 + 快照组包 | 1.5 KB | 1.5 KB | 1.5 KB | 56×2 B + ISO-TP 120 B ×2（收发） |
| console/printf 池 | 0.5 KB | 0.5 KB | 0.5 KB | 4×128 B per-task |
| **合计峰值** | **≈ 43 KB** | **≈ 46 KB** | **≈ 42 KB** | |
| **余量** | 85 KB（66 %） | 82 KB（64 %） | 86 KB（67 %） | 健康；`free_heap(0x1E)` 上云监控 |

**监控要求**：`uxTaskGetStackHighWaterMark()` 每分钟采样写入 `0x1E free_heap` + 各任务水位进 `status` 主题；
任一任务栈水位 < 64 B 视为未通过验收（A-10）。这是 FreeRTOS 项目最容易在真机跑 24 h 后才炸的项。

### 6.2 Flash

| 项 | 估算 |
|---|---|
| v2.0 基线 Code | 31.4 KB |
| + FDCAN/can_router/bridge | +12 KB |
| + FreeRTOS + 任务化改造 | +10 KB |
| + ISO-TP/UDS（已存在，搬入） | +6 KB |
| + MQTT-C + esp_at（仅 M2） | +14 KB |
| + JSON 组包（整数格式化，无 `%f`） | +6 KB |
| + ADC 采集 | +3 KB |
| **M2 合计** | **≈ 82 KB / 512 KB (16 %)** | 

余量充足，可开 `-O1` 便于调试、可留 OTA 双分区（本项目不做 OTA，列未来项）。

## 7. 时钟与总线核算（可复核）

```
HSE 8 MHz → PLL: /M=2 → 4 MHz → ×N=75 → 300 MHz → /R=2 → 150 MHz SYSCLK
AHB = 150, APB1 = APB2 = 150 MHz (全 /1)

USART3 @115200, OVERSAMPLE=16, PCLK1=150 MHz
  USARTDIV = 150e6 / (16 × 115200) = 81.3802  → BRR = 81<<4 | round(0.3802×16)=6 = 1302  ✔ 与代码注释一致
  位时间 = 1/115200 = 8.680 µs；字符(11 bit) = 95.5 µs；t3.5 = 334 µs ✔

FDCAN 内核 = PCLK1 = 150 MHz, Prescaler 30 → tq 200 ns, 10 tq/bit → 500 kbit/s, SP 80 % ✔
  标准帧 8B 数据 ≈ 108 bit ≈ 216 µs/帧

SPI1 W25Q128: 150 MHz / 16 = 9.375 MHz（注释误标 10.6 MHz）
  页编程 256 B @9.375 MHz ≈ 256×8/9.375e6 = 219 µs + 典型 tPP 3 ms（W25Q 规格上限 20 ms）
  → 单次 LOG_WriteEvent 阻塞最坏 ~20 ms，必须出主路径（决策 4/T5）
  扇区擦除 4 KB：tSE 典型 45 ms / 上限 400 ms → 轮转擦除期间的 400 ms 阻塞是 A-04 的观测重点
```
**这些数字是验收时的对照值**，不是注释。任何时钟树改动都要回到这里重算。
