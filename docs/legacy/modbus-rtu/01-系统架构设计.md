# 01 系统架构设计

## 1. 系统定位

两块完全相同的 Genbotter STM32G474VET6 开发板构成 RS485 主从双节点：

- **A 板（Master）**：周期轮询从站、读写寄存器、超时重试、通信统计、错误统计、CLI 调试。
- **B 板（Slave）**：接收请求、地址判断、CRC 校验、功能码解析、寄存器读写、异常响应、
  参数管理（24C02 掉电保存）、故障日志（W25Q128）、LCD 状态显示、按键。

两块板硬件一致，固件通过编译期宏区分角色（见 `BSP/bsp_board_cfg.h`）。

## 2. 分层结构

```
┌────────────────────────  App  ────────────────────────┐
│  system_manager(状态机) device_manager(寄存器数据源)    │
│  master_app / slave_app（角色逻辑）                    │
├──────────────────────  Protocol  ─────────────────────┤
│  modbus_crc / modbus_register / modbus_master /        │
│  modbus_slave（帧解析、异常响应，平台无关）             │
├────────────────────────  BSP  ────────────────────────┤
│  bsp_uart / bsp_rs485(DE时序) / bsp_led / bsp_key /    │
│  bsp_eeprom(24C02) / bsp_w25q128 / bsp_lcd             │
├──────────────────────  Storage  ──────────────────────┤
│  config(参数区: 版本+CRC) / log(环形日志)              │
├──────────────────────  Common  ───────────────────────┤
│  types / ring_buffer / crc（纯 C，可在 PC 侧编译测试）  │
└────────────────────────  Core  ────────────────────────┘
   CubeMX 生成的启动/HAL/时钟/中断 + main 入口
```

分层原则：
1. **Protocol / Common 不依赖 HAL**，用 `types.h` 自定义类型，便于 PC 单测与移植。
2. **BSP 层自初始化**（参照 `Drivers/User/led.c`）：每个 BSP 内部自行开时钟、配置 GPIO/外设，
   不依赖 CubeMX `.ioc` 重新生成（工程中没有 `.ioc`）。
3. App 层持有"寄存器数据源"与"参数/统计"对象，Protocol 层只做协议编解码。
4. 中断里只做"收字节 + 记时间戳"，帧边界判定放到主循环/状态机（第一版）；
   V1.4 再演进为 DMA + RingBuffer。

## 3. 编译单元与角色

| 文件                       | 归属 | 说明                                   |
|----------------------------|------|----------------------------------------|
| `Core/Src/main.c`          | 双板 | HAL 初始化 + 时钟 + 调用角色入口        |
| `Master/master_main.c`     | A 板 | `#if MODBUS_NODE_ROLE==MASTER` 时编译   |
| `Slave/slave_main.c`       | B 板 | `#if MODBUS_NODE_ROLE==SLAVE` 时编译    |

Keil 工程中通过 C/C++ Define 增加 `MODBUS_NODE_ROLE=MASTER` 或 `=SLAVE` 出两版固件。

## 4. 通信拓扑与数据流

```
Master 主循环：
  POLL → 组帧(CRC) → RS485_TX → 切RX → 等响应(超时定时)
    → 收到帧 → CRC校验 → 解析 → 更新统计/寄存器 → 下一轮

Slave 主循环：
  USART RX 中断收字节 → 帧间隔超时判帧完成
    → 地址匹配 → CRC校验 → 功能码分派 → 执行/异常 → RS485_TX 响应
```

## 5. 与上位机工具

PC Python 工具通过 USB-UART 与 A 板(Master)调试口连接，A 板作为真正的主站轮询 B 板；
工具还支持直连任意一板进行协议注入测试（monitor 模式抓原始帧）。

## 6. 目录职责速查

| 目录       | 内容                                                  |
|------------|-------------------------------------------------------|
| `App/`     | 应用逻辑：system_manager, device_manager, master_app, slave_app, modbus_app |
| `Protocol/`| modbus 帧/CRC/寄存器表/主从协议机（平台无关）           |
| `BSP/`     | 板级驱动：uart/rs485/led/key/eeprom/w25q128/lcd + 板级配置头 |
| `Storage/` | config(24C02 参数持久化)、log(W25Q128 日志环形区)       |
| `Common/`  | types.h、ring_buffer、通用 crc、平台无关公共代码        |
| `Master/`  | A 板角色 main（master_main.c）                         |
| `Slave/`   | B 板角色 main（slave_main.c）                          |
| `Tools/python/` | PC 测试工具（modbus_crc / modbus_master / logger / modbus_tool） |
| `docs/`    | 设计文档                                              |
