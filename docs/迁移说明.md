### 9.2 任务集（新增 `App/app_rtos.c`）

wdt(6) / can(5) / mb(5) / log(2) / ui(1) / console(2 过渡)；T3 bridge、T4 uplink 未建（v0.4 / v0.5）。

- **心跳表**：wdt_task 仅当全部心跳新鲜才喂 IWDG；任一任务超期 → 停喂 → IWDG ≤ 3 s 复位 → 下次开机 `LOG_BOOT` 如实记录复位原因（bit2=IWDG）。
- **故障取证**：HardFault/MemManage/BusFault/UsageFault 保存 PC/LR/CFSR/HFSR 至 RAM 并尝试控制台输出（USART1 就绪前静默，避免 TXE 死等）；FreeRTOS 栈溢出 / 断言 / malloc 失败钩子停机，同样由 IWDG 收口复位。

### 9.3 有意偏离与实现修订（诚实清单）

1. **SysTick/PendSV/SVCall 实际为最低优先级（15）**，而非 docs/04 §5 表中的 (0,0)——这是 FreeRTOS Cortex-M 移植的固定约定（内核 tick 不得抢占可调 FromISR 的中断），按实现更正文档理解。
2. **RS485 RX 仍为 ISR 逐字节回调直喂协议引擎**（v3.0/Modbus v2.0 硬件验证过的路径；t3.5 判定依赖逐字节真时间戳）。ISR 内只有字节累积，协议解析与发送决策都在 `MB_*_Poll`（任务上下文）。与 docs/02 §5 "ISR 只投递"的理想形态的差值记录在案，属性能优化项而非正确性项。
3. **新增 console_task（过渡任务）**：v0.5 上行链路（T4 uplink）落地后并入；docs/02 §3 原任务表未含该任务。
4. `CONFIG_Init` 的首启默认值回写仍发生在 mb_task（一次性 ~5 ms）；周期性/UI 触发的保存才走 log_task。
5. dirty→save 的"读快照与清 dirty 之间的写窗口"语义与 v2.0 完全一致（不修，防行为漂移）。

### 10.2 冻结决策（文档歧义的定案，docs/03 已同步）

1. **哈希输入串精确格式**：`key:PP:SS:RR`，PP=两位**大写** hex，SS=单个数字字符，RR=`RO`/`RW`；行间 `\n`（LF），**末尾无换行**。979 字节，55 行。
2. **行集口径**：dp_table = 0x00–0x37 去 0x0F = **55 行**。docs/03 §5.1 的"56 条 dp 描述"按寄存器槽位计数（含空洞）；快照载荷（v0.4+）仍按 56 槽的连续寄存器块发送，空洞槽值恒 0。
3. **预留槽键名**：`rsv_meas0..12`（0x23–0x2F）、`rsv_ctrl0..2`（0x35–0x37），无方括号——键名同时是 MQTT JSON 字段名，保持纯 ASCII 标识符。
4. **本版实测契约哈希 = `E71B`**（docs/03 中 `"A91F"` 为示意值；三处投影必须以实际计算结果为准）。
5. **0x0F 区间语义**：块访问跨越 0x0F → 异常 0x02（见 10.1）。
