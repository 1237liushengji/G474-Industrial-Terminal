## 2. 冲突消解表（9 条，逐条决议）

| # | 冲突 | 决议 | 落点 |
|---|---|---|---|
| 1 | **PB10/PB11 双重归属**：RS485 vs ESP-12F（AF 表唯一复用，硬互斥） | 由 `USART3_OWNER` 单点决断；M1→RS485(A 主/B 从)，M2→A 板给 ESP、RS485 全下移 B 板 | 00 号文档 D-02/§3；04 号文档 §1 |
| 2 | **两个 `bsp_uart.c/h`**：[C] 版服务 USART1+console（128 B ring、`Printf` 96 B 静态池、`Send` 阻塞 100 ms）；[M] 版服务 USART3+双模式 RX（DMA/中断、`IRQHandler` 宏展开） | **取 [M] 版为唯一 `BSP/bsp_uart.c`**（能力超集），把 [C] 的 `BSP_UART_Printf` 移植为 `Common/bsp_printf.c`（per-task 缓冲池 + mutex）；[C] 的 USART1 特定部分由 `RS485_UART_PERIPH` 式宏参数化（[M] 版已是宏驱动外设号，天然支持第二个 UART 实例） | v0.1 |
| 3 | **两套 ring buffer**：[C] 在 `can.c`/`bsp_uart.c` 内联 SPSC（`__DMB()` 发布序，无 PRIMASK 临界区）；[M] 有独立 `Common/ring_buffer.c` | 队列化后 **FDCAN ring 删除**（02 号文档决策 1）；UART 字节流保留 `Common/ring_buffer.c`，其 `CAN_RX_RING_LEN=16` 提升为 `CAN_RX_Q_LEN=32` | v0.2 |
| 4 | **两套时基**：[C] 只有 `HAL_GetTick()`（无 `get_tick`、无显式环绕安全比较，靠 `(int32_t)(tick-due)>=0` 与 `now-last>=PERIOD` 无符号环绕技巧）；[M] 有 `BSP_Tick_GetUs()`（DWT） | **三轨制**（02 号文档 §5 决策 3）。环绕比较惯例保留并写成 inline helper `time_after(a,b)`，禁止散落裸比较 | v0.2 |
| 5 | **CAN 工程无 LCD/按键/EEPROM/Flash**：`E:\STM32\CAN` 里 `未找到` bsp_lcd/bsp_key/bsp_eeprom/bsp_w25q128，README §1.4 只登记了占用 | 全部取 [M] 版。[C] 的 A 板因此"从零获得"HMI/存储能力，这是合并的直接收益 | v0.1 |
| 6 | **`CAN_NODE_ROLE`(can.h:41) vs `MODBUS_NODE_ROLE`(bsp_board_cfg.h:27)** 双角色宏 | 合并为 `NODE_ROLE` 单宏，由 Keil Define 注入；`CAN_NODE_ROLE`/`MODBUS_NODE_ROLE` 改为派生只读别名并在 v0.1 结束后删除 | 04 号文档 §1/§2 |
| 7 | **`HAL_MODULE_ENABLED` 集合不同**（[C] 有 FDCAN 无 SPI/I2C/DMA；[M] 反之；两边 CRC 都关、TIM 都不用） | 取并集 + 新增 ADC/TIM6；显式锁 HAL **V1.2.3 / DFP 2.2.0** 不升级 | 04 号文档 §4 |
| 8 | **两套上位机**：`[C]/tools/can_console.py` 与 `[M]/Tools/python/*` | 合并为 `Tools/python/{can,modbus,mqtt,verification}/`，共用一份 `requirements.txt`（新增，两工程都没有）与 `runner.py` 顶层入口 | v0.5 |
| 9 | **`LOG_Read(index)` 语义不足**：返回"RAM 缓存内最旧"，缓存 `LOG_CACHE_CAP=512`（=16 KB RAM），且 `LOG_Init` 线性扫 64 KB 是**阻塞、在 RS485 初始化之前** | ① 缓存降 128 回收 RAM；② 新增 `LOG_ReadBySeq(seq, rec*)` 直读 flash（补发必需）；③ 扫描挪进 `log_task`，启动期只置 `s_scanning` 标志；④ `LOG_WriteEvent` 的阻塞页编程进 `log_task` | 02 号文档决策 6 |

## 4. 合并前置动作（v0.1 第一步，勿跳过）

1. `git -C E:\STM32\Modbus-RTU status --short` → `M BSP/bsp_board_cfg.h`（role 被从 SLAVE 翻成 MASTER）。
   **在原仓 commit 或 `git stash`**，不要让它以未提交状态进入新仓。
2. `git -C E:\STM32\CAN\CAN双机通信 status` → `M G474/MDK-ARM/G474.uvprojx/.uvoptx`。同上处理。
3. 两仓各打一个"final snapshot"标签或记录当前 commit hash 到新仓 `docs/迁移说明.md`，
   使新仓每个搬入文件都能回指来源 commit（保留 `git log --follow` 的可追溯性 → 建议用 `git filter-repo`
   或 `git subtree add` 而非纯 `cp`，代价是多半天工作量，收益是历史可查 —— **v0.1 决策项，需要你先表态**）。
4. 从 [C] 与 [M] 各拷一份 `Drivers/`（HAL V1.2.3 + CMSIS）→ **比对是否同版本**，取一份。两边 DFP 都是 2.2.0，
   但 [C] 的 `stm32g4xx_hal_conf.h` 曾把 `HAL_CRC_MODULE_ENABLED` 注释掉，拷贝时勿覆盖成两份不同的 conf。
5. 先跑一次两条既有回归（`python Tools/python/run_tests.py`；`node Tools/verification/crc_check.js`）
   留一份基线输出作为"迁移前绿色"凭证。这一步能在合并出问题时立刻区分"搬坏了"还是"本来就是红的"。
