## 2. 板上到底有什么（推翻若干既有假设）

实物器件清单（正反面丝印 + 实物照片）：`U1` STM32G474VET6、AMS1117 LDO、**板载 ESP8266 模块（焊装）**、
**W25Q128（SPI1：CS=PA4/SCK=PA5/MISO=PA6/MOSI=PA7）**、**24C02（I2C1：SCL=PA15/SDA=PB9）**、
USB-C、1.69″ LCD FPC 座、SWD/USART1 调试座、`J3` BOOT 跳线、`SW1` 复位键、**三颗用户按键**（PA0/PA2/PA3）、
**两颗 LED**（PE0 蓝 / PE1 绿）、8 MHz + 32.768 kHz 晶振、CR1220 电池座、以及 **三组跳线帽焊盘**
（CAN：PB12/PB13；485 与 WiFi 共用 PB10/PB11）。

| 接口 | 实物真相（丝印） | 备注 |
|---|---|---|
| CAN | 跳线帽接 `CAN_RX->PB12 / CAN_TX->PB13`（FDCAN2, AF9） | v3.0 工程实机跑通 |
| 485 | 跳线帽接 `485_RX->PB10 / 485_TX->PB11`（USART3, AF7） | 原 Modbus 工程实机跑通 |
| WiFi | 跳线帽接 `WIFI_RX->PB11 / WIFI_TX->PB10`（LPUART1, AF8） | **与 485 共用 PB10/PB11，二选一** |
| W25Q128 | SPI1：PA4/PA5/PA6/PA7（CS 软片选） | 板上芯片，原工程配置 |
| 24C02 | I2C1：PA15/PB9 | 板上芯片 |
| 按键 | WKUP=PA0（闲低按高）、K0=PA2、K1=PA3（#=低有效） | 三键 |
| LED | 蓝=PE0、绿=PE1（低电平点亮） | 两灯 |

**电源**：`5V → AMS1117 → 3.3V`，输入侧 `10µF+0.1µF`，输出侧 `0.1µF+10µF`，两侧各有一只 ESD 管。
AMS1117 属线性 LDO，5V→3.3V 时**每 100 mA 负载耗散 0.17 W**；ESP-12F 发射峰值 300–400 mA →
额外耗散 0.5–0.7 W，SOT-223 封装需良好铺铜，且**板上 3.3V 轨只有 10 µF 储能**。
→ 见 §8 遗留项 R-4'。

**用户已确认持有**：USB-TTL 串口线 ✅、外接 24C02 模块 ✅、外接 W25Q 模块 ✅。
**仍未持有**：USB-RS485 转换器 ❌、USB-CAN 适配器 ❌。

## 4. 冲突裁决（7 条）

> ⚠ **2026-10-07 终审：本节 7 条裁决（尤其 C1/C2/C3）基于错误原理图，已整体作废。**
> 真相：CAN 在 PB12/13 与 Flash（实为 PA4-PA7）**不冲突**；485 与 WiFi 才真正共用 PB10/PB11
> （跳线帽二选一，分属 USART3 / LPUART1）。消解矩阵见 [迁移说明 §17](迁移说明.md)。

### C1（严重）板载 W25Q128 与 FDCAN2 抢 PB12/PB13

`PB12 = FDCAN2_RX`（AF9）同时是板载 Flash 的 `CS#`；`PB13 = FDCAN2_TX`（AF9）同时是 `SPI2_SCK`（AF5）。
**同一引脚不可能同时是 FDCAN 和 SPI 复用** → 二选一。

**裁决（用户选定）**：CAN 改用 **FDCAN1 on PD0/PD1（J1 19/20）**，**保住板载 16 MB Flash**。

代价核算：
- 位时序**不变**：FDCAN1/FDCAN2 共用同一内核时钟选择（`RCC_FDCANCLKSOURCE_PCLK1` = 150 MHz），
  Prescaler 30 / Seg1 7 / Seg2 2 / SJW 2 → 500 kbit/s、采样点 80 % 原样成立。
- `can.c` 590 行**与实例无关**（全部通过 `hfdcan` 句柄），且其记录的三处 HAL V1.2.3 陷阱属于 **FDCAN IP 行为**，
  不是 FDCAN2 特有 → 规避代码原样适用。
- 实际改动面：`stm32g4xx_hal_msp.c`（实例/引脚/`__HAL_RCC_FDCAN_CLK_ENABLE`/NVIC 线）、
  `stm32g4xx_it.c`（`FDCAN1_IT0_IRQHandler`）、若干宏。**约 30 行。**
- 必须重跑：A-03（丢帧核算）、A-04（bus-off 恢复）。这是切换的唯一实质成本，已列入 v0.2 出口条件。

### C2（原判过重）RS485 与 ESP-12F 抢 USART3 —— 不是死结

原判"PB10/PB11 只有 USART3 一个复用，故板载 RS485 与 WiFi 硬互斥"在**引脚层面**成立，
但前提"两者都在板上"是错的 —— 两者都是外接模块，接线可改。而 USART3 的可选引脚对远不止 PB10/PB11（Table 12）：

| USART3 引脚对 | 位置 | 可用性 |
|---|---|---|
| PB10(TX) / PB11(RX) | J2 20 / 17 | 给 ESP-12F（背板丝印标注处） |
| PD8(TX) / PD9(RX) | J2 14 / 11 | 空闲 |
| PC10(TX) / PC11(RX) | J1 16 / 17 | 空闲 |
| PB9(TX) / PB7(RX) | J1 33 / 31 | PB9 被 24C02 的 I2C1_SDA 占用 ✗ |
| PE15(RX) | — | TX 无对应 |

**裁决**：RS485 不再抢 USART3，改用 **USART2**；**ESP-12F 独占 USART3(PB10/PB11)**。
→ **两块板可同时拥有 RS485 + WiFi + CAN**，原 M1/M2 互斥形态**作废**（§5）。

### C3（由 D 级实测引入）RS485 不能落在 USART2 的 PA2/PA3

USART2 的默认对是 `PA2(TX)/PA3(RX)`，但用户实测**按键 K0/K1 就在 PA2/PA3**（`2.KEY` 例程亦用 PA2）。
USART2 的其它可选对：`PD5/PD6`（空闲 ✓）、`PA14/PA15`（SWD + I2C1_SCL，占用 ✗）、`PB3/PB4`（PB3 = LCD_SCL，占用 ✗）。

**裁决**：**RS485 → USART2 on PD5(TX)/PD6(RX)，J1 pin 24/25**。
- 外设仍是用户选定的 USART2，只是换引脚对；
- 按键、ESP-12F、LCD、24C02 全部不动；
- USART2 挂在 APB1（150 MHz），与 USART3 同频 → 既有 `bsp_uart.c` 的 `BRR` 计算（由 `HAL_RCC_GetPCLK1Freq()` 实时推导）**无需改动**，115200 下同样是 1302。
- 既有 BSP 已是宏驱动（`RS485_UART_PERIPH/_IRQn/_IRQHandler/_CLK_ENABLE()` + TX/RX 端口/引脚宏）
  → 换 USART2 **纯宏改动**，`bsp_rs485.c` / `bsp_uart.c` / 协议层零改动。

### C4 USB-C 占用 PA11/PA12

`PA11 = USB_D-`、`PA12 = USB_D+`，且 `CC1/CC2` 各经 5.1 kΩ 下拉（标准 UFP 受电配置）。
→ PA11/PA12 不可改作它用。**但可被动用为 USB CDC 虚拟串口**，作为 USART1 之外的第二条 PC 链路（见 §6 选项）。

### C5 PB8 = BOOT0，不可用

原理图网络 `PB8-BOOT0` 经 `R8` 连到 BOOT0；`J3` 是 BOOT 跳线。
→ **PB8 排除**出所有候选（它原本是 FDCAN1_TX / USART3_TX 的备选之一，现已排除）。
BOOT0 走 PB8 而非专用引脚，意味着**上电瞬间 PB8 的电平决定启动模式** —— 因此 PB8 上不能挂任何
下拉/干扰源，本项目不使用该引脚。

### C6 PA15 与 PB3 属 SWJ 引脚

`PA15 = JTDI`（本板用作 24C02 的 I2C1_SCL）、`PB3 = JTDO/TRACESWO`（本板用作 LCD_SCL）。
→ 调试器必须锁定 **SWD 2-pin（仅 PA13/PA14）**，禁止启用 JTAG 或 Trace，否则 I2C1 与 LCD 同时失效。
此条与 00 号文档 R-1 一致，风险等级**维持**：Modbus 工程把 24C02 列为"待真机"，此处是首要怀疑对象。

### C7 PB10/PB11 是 TT 型（非 5V 容忍）

数据手册 Table 12：`PB10 I/O TT_a`、PB11 同为 TT。TT = **仅 3.3 V 容忍**。
→ 接在 PB10/PB11 上的 ESP-12F 也是 3.3 V 逻辑，✅ 安全。
→ 但 **RS485 模块必须选 3.3 V 逻辑版本**（MAX3485 / SP3485 / SIT3485 等）。
若手上是 5 V 的 MAX485 模块，其 `RO` 输出 5 V 会超压损坏 PD6 —— 必须改用 3.3 V 版或加电平转换。
**这是本项目最容易烧板的一处，已升级为风险 R-8。**

## 5. 修正后的系统拓扑（取代 00 号文档 §3 的 M1/M2）

> ⚠ **2026-10-07 终审：本节拓扑基于错误引脚，仅作历史；实际拓扑以迁移说明 §17 跳线矩阵为准。**

原 M1/M2 双形态的成因是"单板不能同时有 RS485 与 WiFi"。C2/C3 之后该成因消失：

```
        ┌──────────────────── A 板 · GATEWAY ────────────────────┐
        │ USART2 / PD5,PD6  → RS485 模块 → Modbus RTU 主站        │═══ RS485 总线(A/B) ═══┐
        │ USART3 / PB10,PB11 → ESP-12F #1 → MQTT-C 设备侧上云      │                      │
        │ USART1 / PA9,PA10 → console（USB-TTL，或 J4 调试座）      │                      │
        │ FDCAN1 / PD0,PD1  → CAN 收发器 ────── CAN 500 kbit/s ────┼──────────────────────┤
        │ SPI2 / PB12-PB15  → 板载 W25Q128 16MB：日志 + 待发缓存    │                      │
        │ I2C1 / PA15,PB9   → 24C02：网关参数                      │                      │
        │ LCD + LED PC0 + KEY PD15                                │                      │
        └─────────────────────────────────────────────────────────┘                      │
                                                            CAN 500k                     │
        ┌──────────────────── B 板 · NODE ───────────────────────┐                      │
        │ USART2 / PD5,PD6  → RS485 模块 → Modbus RTU 从站       │══════════════════════┘
        │ USART3 / PB10,PB11 → ESP-12F #2（可选：第二条上云通道） │
        │ USART1 / PA9,PA10 → console                            │
        │ FDCAN1 / PD0,PD1  → CAN 收发器                          │
        │ SPI2 → 板载 W25Q128（日志）；I2C1 → 24C02（现场配置）    │
        │ LCD + LED/KEY + 本地采集 + 离线自治                      │
        └─────────────────────────────────────────────────────────┘
                                   │ USB-RS485（仍未持有）
                                   ▼ PC: Mosquitto :1883 + Tools/python（Modbus 主站/观测者）
```

**关键性质**
1. **两板结构同构**：同一套固件、同一份引脚表，只靠 `NODE_ROLE` 分主从。烧错固件的风险从"链路不通"
   降为"主从颠倒"（症状明确、方向可判）。
2. **两条独立上行路径可同时在线**：A 板经 ESP-12F 直连 MQTT（主路径），A 板 USART1 经 USB-TTL 到 PC
   （console + 影子网关，备用/调试路径）。**PC 影子网关从"M1 形态"降级为"可选旁路"**，但仍保留 ——
   它是断网实验和 A-06 双路比对的手段。
3. **RS485 段由两板自身闭环**，不再依赖 PC 接入。USB-RS485 只用于"PC 作为第三方观测者"（A-06/A-11）。
4. **两片 ESP-12F 都有用**：A 板主上云，B 板可选第二条上云（B 板离线自治时也能上报）。

## 6. 修正后的板级配置点（取代 04 号文档 §1 中的对应宏）

> ⚠ **2026-10-07 终审：本节宏表作废；实际宏见 `BSP/app_board_cfg.h`（已按丝印重写）。**

```c
/* ---- CAN：改用 FDCAN1 ---- */
#define CAN_USE_FDCAN            1u            /* 1=FDCAN1(PD0/PD1,板载Flash可用)  2=FDCAN2(PB12/PB13,回退用) */

#define CAN_TX_PORT_PIN          GPIOD, GPIO_PIN_1

/* ---- WiFi（新增）---- */
#define ESP_UART_PERIPH          USART3
#define ESP_TX_GPIO_PORT_PIN     GPIOB, GPIO_PIN_10
#define ESP_RX_GPIO_PORT_PIN     GPIOB, GPIO_PIN_11

/* ---- 板载 Flash：SPI2（不再是 SPI1/PA4-PA7）---- */
#define FLASH_SPI_PERIPH         SPI2

#define FLASH_MISO_PORT_PIN      GPIOB, GPIO_PIN_14

#define FLASH_EXPECTED_JEDEC     0xEF4018u     /* W25Q128 = EF 40 18，上电必须校验 */
#define LOG_AREA_SIZE            (256u * 1024u) /* 板载 16MB 后可从 64KB 扩到 256KB */

**`bsp_w25q128.c` 的改动**：把硬编码的 SPI1/PA4-PA7 全部改走上述宏（当前该文件只部分走宏、I2C 引脚则完全硬编码，
